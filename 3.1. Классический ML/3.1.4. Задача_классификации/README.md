# 3.1.4. Задача классификации

В работе решается задача прогнозирования поломки промышленного оборудования в следующие 6 часов.

## Целевая переменная

`failure_next_6h`:

- `0` — поломки не будет;
- `1` — поломка произойдёт в следующие 6 часов.

## Выполненные этапы

- исследован баланс классов;
- проанализирована связь признаков с таргетом;
- выполнено хронологическое разделение данных;
- обработаны пропуски;
- числовые признаки стандартизированы;
- категориальный признак закодирован методом One-Hot Encoding;
- обучена модель KNeighborsClassifier;
- подобрано количество соседей;
- построены Precision–Recall и ROC-кривые;
- выбран порог классификации;
- построена матрица ошибок;
- рассчитаны метрики качества.

## Результат

На validation-выборке лучшая модель использовала приблизительно:

- 7 ближайших соседей;
- взвешивание по расстоянию;
- порог около 0,308.

На тестовом временном периоде модель показала качество, близкое к случайному классификатору:

- ROC-AUC — около 0,50;
- PR-AUC — около 0,011;
- Recall — 0;
- F1-score — 0.

Основная причина низкого качества — сильный дисбаланс классов и слабые различия между признаками перед поломкой и при нормальной работе.

Модель не подходит для практического применения. Для улучшения необходимо создавать временные признаки и проверять другие алгоритмы классификации.
